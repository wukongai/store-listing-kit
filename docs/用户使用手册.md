# 微信小店上架 Skill：安装与使用手册

上架一个产品，要准备文案、图片、视频，还得对着后台挨个找文件。这个 Skill 帮你把这些工作整理成一套流程，最后交付一份 **HTML 交接清单**：按后台顺序复制文案、预览素材、复制文件路径，做完一项勾选一项。

适合准备上架课程、数字资料、训练营或服务的个人与小团队。换一个商品，继续用同一套流程。

## 1. 获取并安装

源码仓库：https://github.com/wukongai/store-listing-kit

在支持 Skill 和本地文件操作的 Agent 中使用，例如 Codex、Claude Code。电脑需有 Python 3.10 或更新版本；图片检查需要 Pillow。通过下面命令安装还需要 Node.js 和 npx。

```bash
npx skills add wukongai/store-listing-kit
```

这条命令会获取仓库中的 Skill，按提示选择 `store-listing-kit` 和你使用的 Agent。视频子技能按需选择。私有仓库需要先获得访问权限；若你拿到的是 ZIP，把它完整解压，再请 Agent 安装其中的 `skills/store-listing-kit` 目录，保留内部文件结构。

也可以直接把下面的话发给 Agent：

```text
请帮我安装 store-listing-kit：
https://github.com/wukongai/store-listing-kit
检查安装所需环境，按当前 Agent 的 Skill 安装方式完成，并确认能够识别这个 Skill。
```

**首次使用，告诉 Agent 你的 Obsidian 知识库根目录、已有产品目录和素材输出位置。** 它会按这些信息检查归档路径。你不需要修改脚本；也不要使用作者电脑上的路径。当前版本按 OB 产品目录归档，没有知识库时先建立自己的知识库和产品目录，再开始制作。

## 2. 准备三样资料

- **产品资料**：产品是什么、适合谁、解决什么问题、包含什么、怎样交付。课程可以提供大纲、讲义和工具包。
- **后台截图**：商品上架页的完整截图，包含字段、图片要求和上传位置。可用 GoFullPage 截全页，也可分段截图。
- **已有素材**：产品图片、品牌配色、海报模板、真实讲师资料等。没有的就说明需要制作。

价格、服务期限、售后和实际交付范围由你确认。信息不全时，Agent 应列出缺项，不替你编造。

## 3. 把任务交给 Agent

复制下面这段，把方括号中的内容换成自己的资料：

```text
用 store-listing-kit，为这个产品准备微信小店上架素材包。

产品资料：[文件位置]
后台截图：[文件位置]
已有素材：[文件位置，没有就说明]
OB 知识库：[根目录]
产品目录：[已有产品目录]
输出位置：[该产品下的营销上架目录]

先分析后台，整理工作资料包和 TODO，列清每项任务、产物与保存位置。
按已确认的产品事实制作文案和图片；需要视频时调用已接入的产品营销视频能力。
最后生成可复制、可预览、可勾选的 HTML 交接清单。
缺少真实业务信息时问我，保留旧版本，不混入其他产品的素材。
```

Agent 会依次完成：**读要求 → 整理资料与 TODO → 制作文案和素材 → 检查文件 → 生成交接清单。**

图片制作需要另行接入 image-factory 及可用的生图能力。需要商品介绍视频时，再接入配音和视频工厂；也可以先使用自己已有的图片和视频。**这个 Skill 负责组织流程，不内置图片、配音或视频生成服务。**

## 4. 打开 HTML 清单，完成上架

在交付目录里打开 **`打开这里.html`** 或 **`00-后台上传TODO.html`**。

清单已经按你的后台顺序排好。每一项会告诉你该填什么、使用哪个文件，以及有没有待补内容：

1. 文案直接复制，粘贴到对应栏目。
2. 图片和视频查看预览，按清单里的文件链接或完整路径定位上传文件。
3. 填完一项就勾选，继续下一项。

**不用在文件夹里来回翻，一个 HTML 页面就能把交接说清楚。** 分享或移动素材包时，请保留整个目录结构，不要只发 HTML，否则图片和文件链接可能打不开。浏览器不允许一键复制时，按页面提示手动复制即可。

勾选进度保存在当前浏览器中；它代表你的操作记录，不代表平台已经审核通过。当前 Skill 交付本地素材与清单，不自动登录、上传或发布商品。

## 换一个产品怎么用？

```text
继续用 store-listing-kit，为这个新产品制作上架素材包。
复用上次的目录结构和设计模板，单独建立新产品目录。
文案、价格、权益、图片和交付文件全部以本次资料为准。
```

换平台也可以沿用这套方法，重新提供该平台的后台截图与要求即可。如果后续接入平台可用的商品 API，可进一步扩展自动上传和填写；该接口能力不包含在本仓库中。

## 遇到问题先看这里

- **Agent 找不到 Skill**：确认装到了当前 Agent 使用的目录，重新打开会话，让它检查安装位置。
- **图片没有生成**：检查是否已接入图片工厂和可用生图服务；也可先提供现成图片。
- **找不到产物**：让 Agent 给出本次产品目录与 HTML 入口的完整路径。
- **价格或资质显示待补**：补充真实信息后，让 Agent 更新清单并重新检查，不把待补项当成完成。

先用一个商品走完这套流程。以后重复的是方法，省下来的是每次重新找资料、做素材和找文件的时间。
