# OB产品营销资料归档

1. 从local-vault.json取得本机知识库根路径，确认目录存在；路径失效时询问用户，不创建替代知识库。
2. 从产品名、当前资料的归属、已有产品README和目录定位对应产品。当前工作目录只有在确实属于该OB产品时才可直接使用。仅同名不算确定映射。
3. 优先复用产品内现有的营销上架、营销素材、销售素材、02 上架资料等专用目录；多个候选用既有索引决定，无法决定则询问。确实没有时在已明确的产品根下新建「营销上架」。
4. 一款独立商品只使用一个固定产品文件夹：营销目录/商品名/。内部固定为「当前上架素材」「历史版本」「制作记录」；日期和版本号只出现在历史版本或制作记录中。修订前快照到历史版本，再更新当前上架素材，保持用户上传路径稳定。多个商品各自独立清单和入口，总索引仅导航、不复制一套商品包。已有目录先映射；批量迁移旧目录要单列链接影响与回滚清单，审批拒绝后保留旧目录并先更新固定入口。
5. 路径检查要解析符号链接，最终路径仍在OB产品内部；产品目录必须已存在，不能把知识库根本身当产品。
6. 最终产物包括图片、文案、交付包、预览、package.json和核验记录；临时生成缓存只作中间材料，必须复制回正式归档位置。
7. 营销目录留下Markdown索引，包含产品名、当前版、历史版、各商品素材入口与状态；在Obsidian内能搜索产品名找到入口。旧索引修改前备份，保留人工段落和历史路径，不删除旧包。
8. 交付前核对索引每条本地链接存在，报告OB绝对路径。路径检查只验证归属边界，不能代替产品语义匹配或目录选择。

用户要求营销目录只保留产品文件夹时，总索引移到产品上级或产品README中。其他旧包归入用户指定BK，保留完整迁移记录及原文件，收到明确归档授权后执行。
