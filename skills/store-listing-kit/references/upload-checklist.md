# 可复用的后台上传清单

每个新商品默认交付可勾选的 HTML 上传清单。使用 scripts/render_upload_checklist.py，根据素材目录内 upload-checklist.json 生成打开这里.html、00-后台上传TODO.html、00-后台上传TODO.md。无需另写产品专属生成器。

## 输入合同
- product_id：每个商品首次创建时生成 UUID，之后保持不变；不同商品不得复用。
- revision：本次清单版本；内容或步骤实质变化时更新，避免旧勾选误当新版本已完成。
- title、summary：商品名称与操作说明。
- scope：standalone（独立商品）、bundle（套装/训练营）、service 或 physical。
- note：本次仍未落实的真实业务事项。
- steps：按实际后台顺序排列；每项有稳定 id（小写英文、数字、横线或下划线）、title、status、instruction、files。
- status：ready 仅表示本地资料已备齐；pending 为待完成；optional 为可选。
- files：素材目录内相对文件路径，精确列出当前版文件，不扫描整个目录或混入旧版。不允许绝对路径、越界、符号链接。ready 引用缺失文件会报错；pending 缺文件显示提示且不生成失效链接。

执行：
```sh
python3 -B scripts/render_upload_checklist.py "<对应商品的当前上架素材目录>"
```
此命令写本地 HTML/Markdown，已有入口自动备份到旁边的历史版本；不上传、不开通账号、不发布。文件路径和内部待办只留在商家清单，不进入对外文案。

## 单课与训练营
独立商品对外按真实名称介绍，不自动沿用课程体系中的关卡序号。每个模块说清楚具体成果和用途；涉及AI时说清输入、操作与人工确认。
训练营需另外明确包含哪些课程、工具及服务，各模块当前可交付状态、学习顺序、期限、账号权限。不能把单课包当训练营包，也不能把计划内容表述为全部已交付。套装和单课重复内容明确说明。

## 后台顺序
读取用户当前后台截图或可访问页面后确定顺序，18步只是历史案例，不是固定平台规范。通常包括基础信息、参数、资质、大纲、视频（可选）、方主图、竖主图、白底图（可选）、详情图、文字描述、规格价格库存、发货售后、账号开通与领取、实际交付文件、预览提交。不同平台与商品可增减或重排。

## 生成前后检查
所有准备状态来自实际文件和业务证据。未确认的价格、时限、有效期、兑换地址、账号开通路径只能放 pending 步骤，不拼成最终承诺。勾选是用户本浏览器记录，不证明后台已填或审核通过。
生成后检查链接、图片预览、文案复制、完整路径复制和勾选保存；进度按 product_id + revision 隔离，支持重置。剪贴板不可用时提示用户快捷键复制。
复用 references/upload-checklist.example.json 的字段结构，替换全部示例值；保留已确认的当前产品事实，不继承上一产品的价格、权益或交付路径。
