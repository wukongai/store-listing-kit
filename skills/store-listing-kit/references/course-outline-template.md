# 课程大纲制作标准

证据：用户2026-10-14提供的微信课程大纲模板截图。截图说明“格式与内容仅供参考”“格式无固定要求”。本合同提取信息要求，不把黄色背景、框线或示例课数当强制规范，不保证审核通过。

## 制作前必须核对
1. 商品领域：具体教学领域，不能只写“成长”“赋能”。
2. 大纲目录：课程内容概述、教学方式、亮点、重点、课时数、章节主题、课时标题。
3. 面向人群：实际目标人群及所需基础能力；年龄、职业、兴趣按相关性描述，不虚构门槛。
4. 课程有效期：观看期限及起算条件；其他教学服务周期单列。
5. 各标题清晰概括内容，可用“重点内容”进一步说明。不能只堆“第1课、第2课”，不能用模糊别名、拼音、缩写掩盖教学内容。

## 结构化底稿
每个章节含真实主题；章内课题/学习单元含完整标题、教学重点、学习成果、来源定位。若平台内没有分课，不把图文小节伪装成独立视频课时；使用“学习单元”并如实注明。课时数、音频时长和学员实践耗时分别计算，不能相互替代。预计学习时长须标“预计”与估算依据。

图片总览可保留营销成果，但商品资质大纲须另制详细版，依后台支持分成清晰多页；字不能缩小到无法阅读。图上必须包含基础信息，或与大纲第一页明确对应。正式图片不得出现待确认、XX小时等占位。无法核实的字段列内部缺口，在确认前只交付大纲候选稿。

## 输出与自检
创建 course-outline.json，字段为 domain、teaching_mode、audience、prerequisites、hours、validity、chapters；各章 title、units；各单元 title、key_points、outcome、source。未知值用空字符串/空数组。
运行 `python3 scripts/check_course_outline.py course-outline.json`。这只检查信息结构和占位，不判断宣传真实性或平台政策。与原稿人工逐项对照后再交给 image-factory 出图；大纲、正文、详情与后台参数必须一致。
